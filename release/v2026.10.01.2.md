## 一、一句话定位
**v2026.10.01.1 的修复版（安全版）**。v2026.10.01.1 重做卸载的 18 个包里有 `com.android.htmlviewer`，它其实承载着 SystemUI 开机必需的 CloudSettings provider。卸载后 SystemUI 和锁屏崩溃循环，RescueParty 把手机送进 recovery，提示「清除数据」；用户选了重试，数据没被清。本版把 htmlviewer 移出 removed.txt 并建立**禁删清单**，给开机自检补上**崩溃 / RescueParty / SystemUI 稳定性**检查，并对其余已删包的 534 个 provider 做了同类隐患的静态排查，结论是没有第二个。v2026.10.01 与 v2026.10.01.1 的 removed.txt 都**不要再照着复现**。

## 二、来源与核验
- **事故证据链**（`evidence/reuninstall_20261001/`）：
  - 开机原因历史依次为 `reboot,shell`（07:22:43 验证重启）→ `reboot,rescueparty`（07:24）→ `recovery`（07:25:51）。
  - dropbox 在 07:23:08–07:26:03 记录了 18 次 SystemUI `system_app_crash`，crash 缓冲另有 47 次，全部是 `SecurityException: Failed to find provider com.android.settings.cloud.CloudSettings for user 0`。
  - 堆栈指向 `com.miui.systemui.CloudDataManager.<init>` → `ContentResolver.registerContentObserver`（`incident_stack_CloudSettings.txt`）。
  - `dumpsys package` 证实该 authority 由 `com.android.htmlviewer/com.android.settings.cloud.CloudSettingsProvider` 提供。
  - 另一会话 07:26:39 用 `install-existing` 装回后，崩溃停止。
- **为什么之前没暴露**：v2026.10.01 在 00:23 卸载 htmlviewer 后，几秒内就 `adb reboot`，卸载状态没落盘（见 v2026.10.01.1 的根因）。今早 07:16 重做，是它第一次真正被删掉。
- **为什么验证没发现**：`postboot_check.sh` 初版只核对包状态和设置值，07:23:21 报「全部通过」时 SystemUI 正在崩溃循环（第一次崩溃在 07:23:08）。这是本版要修的第二个问题。
- **新自检的阳性对照**：用事故所在的那次开机（07:25:45）跑新版，正确报出 `reboot,rescueparty` 和 6 次 system_app_crash（装回之前的那几次），SystemUI 稳定一项为通过。
- **干净重启验收**：另一会话在最后一次写入 3 分钟后执行 `svc power reboot`（07:42）。新版自检（`WATCH=90`，本会话另以 `WATCH=20` 独立复跑）**全部通过**：本次开机无系统级崩溃，SystemUI 进程号不变，removed.txt 90 个全部未装，禁删包全部在装，上报开关、锁定 VPN、地区（`zh-Hans-SG`）和时区（`Asia/Singapore`）都保持（`check_after_clean_reboot_0742.txt`）。
- **隐患排查**（`provider_hazard_scan.md`）：反编译 SystemUI 及控制中心插件、桌面、外屏桌面、电话、Telecom、InCallUI、AOD、HyperComm、TouchService、services/miui-services/framework 等，逐一核对 534 个已删 authority 的 observer 注册、`notifyChange`、`call`、`insert`、`update`、`delete` 调用点。**除 htmlviewer 外，没有常驻进程会崩溃**；剩下 5 个低风险调用点都在已删功能的路径上。htmlviewer 至少还有 4 处无保护的调用方（含电话进程），必须永久保留。

## 七、复现
```bash
for p in $(cat debloat/removed.txt); do adb shell -n pm uninstall --user 0 $p; done   # 用本版 removed.txt
# 核对 KEEP.txt 里的包一个都不在上面；等 ≥3 分钟（或直接用 svc power reboot）
adb shell svc power reboot; adb wait-for-device
WATCH=90 ./tools/postboot_check.sh      # 必须全部通过：含「开机以来无系统级崩溃」「SystemUI 稳定」
# 万一 SystemUI 崩溃循环：adb shell cmd package install-existing --user 0 <KEEP 里缺的包>
```
