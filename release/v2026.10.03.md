# v2026.10.03 — permguard：隐私权限定时收回（默认拒绝 + 白名单，无 root）

## 一、一句话定位

Tony：「最好这个脚本可以在手机上定时运行，收回所有 app 关于隐私相关的权限。」

本版新增 `permguard/`。策略是**默认拒绝 + 白名单**：第三方 App 的隐私类运行时权限，加上 MIUI 自有的隐私 appop（广告标识 OAID、获取应用列表、运营商取号、获取运行中应用等），只要不在白名单里，每轮都收回。

执行身份是 shell，有两条通路，跑的是同一份规则引擎：

- adb 版（Mac）
- 手机端：守护循环 + PermGuard App（Shizuku + JobScheduler）

验收只认 `dumpsys package` 和 `cmd appops` 的原值。

## 二、来源与核验

- **权限范围**：
  - 运行时危险权限按组归类：定位（含后台）、通讯录、通话记录、短信、电话、相机、麦克风、日历、传感器/活动识别、媒体与存储、照片位置、附近设备。
  - 加上小米自定义权限 `com.android.permission.GET_INSTALLED_APPS`。在本机 `dumpsys package permission` 查到：由 com.lbe.security.miui 定义，prot=dangerous。
  - 通知权限不算隐私，不收。
- **MIUI op 编号 → 名称**：`cmd appops` 只显示 `MIUIOP(n)`。新增 `Core opnames` 模式，在本机用 app_process 反射 `android.app.AppOpsManager`，实测得到 55 个常量（`evidence/permguard_20261003/opnames.txt`）：
  - 10008 = `OP_AUTO_START`，10021 = `OP_BACKGROUND_START_ACTIVITY`，10022 = `OP_GET_INSTALLED_APPS`
  - 10037 = `OP_GET_OAID`，10039 = `OP_GET_PHONE_NUMBER_OPERATOR`，10054 = `OP_AI_GET_SCREEN_CONTENT` 等
- **默认角色**：`dumpsys role`。角色授予的权限带 `GRANTED_BY_ROLE` 标志，引擎据此自动保留，不靠手写清单。
- **回滚演练**：apply 前先用临时配置只放出 YouTube 相机/麦克风和指南针 10039。
  - apply 后 restore，授予状态、标志、op 模式与快照逐字一致。
  - 再 restore 改回 0 项（幂等）。
  - 演练通过后才正式 apply。
- **Shizuku v13.6.0**：
  - GitHub 下载两次，与 IzzyOnDroid 镜像比对，sha256 三份一致：`6e273ab0…790f`。
  - 签名 CN=Rikka，`268b5590…db30`。
  - Shizuku API 13.1.5 的四个 AAR 来自 Maven Central，sha256 钉在 `app/build.sh`。

## 四、仍保留与理由

- **白名单里标「待 Tony 定」的项**（OPEN_ITEMS #17）：WhatsApp / Telegram / Meet 的相机、麦克风、通讯录；小米录音机（含通话录音）；Bose；eSIM 管理器；Find Hub；Android Auto。原则是宁可少收，不弄坏常用功能。
- **默认助理 Google App**：角色授予读短信、读通话记录、发短信（#18）。要收只能换掉默认助理。
- **剪贴板只报告**：Android 10+ 已禁止后台读剪贴板，再设 ignore 会让所有 App 粘贴失效。
- **特殊权限只报告**：无障碍（Bitwarden）、输入法（Gboard）、常驻 VPN（Clash）。
- **系统 App 只报告**：28 个包的 GET_INSTALLED_APPS 全部是 `SYSTEM_FIXED`。
- **不设 `FLAG_USER_FIXED`**：保留「App 要用时弹窗 → 临时授权 → 下一轮再收」的模型。理由见 `permguard/README.md`。
