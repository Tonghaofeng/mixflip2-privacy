# v2026.10.01.7 — 关闭 Wi-Fi 常扫描、Chrome 遥测、小米离线查找；Clash 新规则实测生效

## 一、一句话定位

用户确认 Clash 已更新，并要求关掉上一版列出的三项。三项都关了，而且都经重启验证。过程中查明：第三项 `OFFLINE_FIND_SCAN` 不是谷歌的，是**小米的离线查找**；它是开机时被云控重写的「支持位」，真正的开关是另一个键。

## 二、来源与核验

- **Clash 新规则在跑**：在手机上用 nc 依次连 `zzhc.vnet.cn`、`typdm.tydevice.com`、`rcpc-sdk-access.m.qq.com`，CMFA 日志分别命中 `DomainSuffix(...) using REJECT`；对照组 `www.google.com` 走 `Match using PROXY[wg-home]`。
- **Wi-Fi 常扫描**：`global wifi_scan_always_enabled` 1 → 0。
- **Chrome 遥测**：Chrome 设置项没有 shell 接口，只能走界面：「⋮ → 设置 → Google 服务 →『帮助改进 Chrome 的功能和性能』」关闭，uiautomator 读回该行开关为 `checked=false`。之后 100 秒里打开维基百科，Chrome 共 5 条连接，**没有一条 beacons.gvt2.com**；此前空闲 5 分钟有 126 条。
- **离线查找归属**：`dumpsys settings` 显示写入方是 `pkg:com.xiaomi.bluetooth`。代码不在主 APK 里，在 `assets/qigsaw/preloadedFeature-master.zip` 这个 Qigsaw 动态插件中（`dumpsys package dexopt` 的二级 dex 记录指向它）。反编译后：
  - `MiuiCloudControl` 每次开机按 `fc_offline_find.json` 云控配置重写 `OFFLINE_FIND_SCAN` / `_SWITCH` / `_NO_NETWORK_BROADCAST` / `_NO_POWER_BROADCAST`（日志 tag `supportFindScan`），所以 shell 把它们改成 0，重启后被写回 1。已实测，第一次重启体检 FAIL 3 项。
  - `OfflineFindScanController.checkOfflineFindDeviceInternal` 只有在 `need_receive_offline_find_broadcast == 1` 且支持位为 1 时，才会把**本机当前位置**记录下来，加密后经 `content://com.xiaomi.finddevice.FcsnProvider` 上报；`need_receive_offline_find_broadcast` 的写入方是已删的 finddevice。
  - 广播侧日志 `broadcast switch is closed`、`isNoNetworkBroadcastOpen: false`：手机断网或关机后的蓝牙信标本来就没开。

## 四、仍保留与理由

- **快连本地 BLE 扫描**（`MiuiFastConnectService` 每分钟一次「start OfflineFindScan」）：服务读的设置里没有明确的用户开关，`is_fastconnect_scan_enable` 是它自己写的状态位；扫描结果的位置记录已被真开关挡住，所在身份（UID 1002）网络已封。
- **Chrome 同页另两项**：「改善搜索和浏览体验」（把访问的网址发给谷歌）、「改进搜索建议」仍开着。不在用户这次同意的三项里，等用户决定。
