## 三、发现

1. **卸载后立刻 `adb reboot` 会丢状态**：卸载后马上 `adb reboot`，user 0 的包状态还没写进 `package-restrictions.xml`。证据是复活的包 firstInstallTime 仍是出厂的 1970，说明不是被重新安装。
2. **htmlviewer 是隐形依赖**：它名为「HTML 查看器」，实际承载 `com.android.settings.cloud.CloudSettings`。SystemUI、KeyguardService 和 com.android.phone 开机就对它注册观察者，而 Android 16 遇到不存在的 authority 直接抛 SecurityException。
3. **设置里藏入口的手段**：shell 能驱动的通用隐藏名单不存在。唯一的官方开关板「应用扩展功能」只能在界面上点，而且早已全关；其余只能靠删包或个别 settings 键。
4. **账号栏只有维修模式标记能藏**：首页账号栏只认 `maintenance_mode_user_id == 110`。全系统 12 个读者里，在「只有 user 0」的前提下真正生效的只有 Settings，代价是不能改锁屏密码。
5. **地区只能改到 locale 层**：真正的地区由 `ro.miui.region=CN` 决定，无 root 改不了；能改的只有 locale 和时区。
6. **体检自身的漏洞**：初版只看包和设置，07:23:21 报了假通过；而且没连设备时，交集为空也会被当成通过。这两个漏洞都已修复。

## 六、踩坑与教训（含失误）

- **验收必须有底层证据**：「重启冒烟通过」不能只看能不能开机，要核对包状态、dropbox 崩溃、boot reason 历史和 SystemUI 稳定性。
- **删包前查 provider**：凡是提供 ContentProvider 的包，删之前先查常驻进程有没有对它 registerContentObserver。只是 `query()` 拿到 null 的无害。
- **系统状态标记**：写这类键之前，先找全系统所有读者。
- **重启时机**：卸载或改设置后至少等 3 分钟再重启，或者直接用 `svc power reboot`。
- **两个会话同时操作一台手机**：写入前互相通知，用一次重启同时验证双方的改动；仓库的 rsync 同步有远端 HEAD 守卫。
- **脚本坑**：zsh 里变量别叫 `path`；`adb pull` 在 while-read 循环里要 `</dev/null`；bash 里 `$S` 后面紧跟全角字符要写成 `${S}`；macOS 的 unzip 解不了中文文件名，改用 Python zipfile。
