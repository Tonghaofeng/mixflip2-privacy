# v2026.10.01.3 — 设置菜单瘦身 + 小米账号删除并隐藏

## 一、一句话定位

参照谷歌原版设置，把 HyperOS 设置里「有外传风险、已经关掉或删掉」的入口从界面上藏起来，让手机不光内部干净，看上去也干净：删除小米账号 `com.xiaomi.account` 并隐藏首页账号栏；关掉并隐藏还在持续扫描的「实时发现周围设备」；隐藏「手机分身」；三指上滑不再指向已删的 AI 应用。全部不需要 root，每一步都能回滚，重启后已复核。

同一天另一个会话发了 v2026.10.01.1 / .2（改地区、重卸 18 个包、htmlviewer 事故修复）。本版建立在 .2 之上。

## 二、来源与核验

**方法**：没有逐页点界面，而是直接从手机拉出 `/system_ext/priv-app/Settings/Settings.apk`（137 MB）用 jadx 反编译，追每个条目的显示条件。对照组是 AOSP android16-release 的 `packages/apps/Settings/res/xml/*.xml`（top_level / privacy / security / apps / display / sound / system 等 15 个）。分 4 组做只读审计：

- 隐私与安全 / 应用 / 账号（这几个页面其实属于 `com.miui.securitycenter`，又反编译了它和 `com.xiaomi.account`）
- 更多设置 / 我的设备 / 更多连接
- 锁屏 / 通知 / 显示 / 声音 / 外屏 / 辅助功能
- 通用隐藏机制

**关键结论（都有 file:line，见 `debloat/settings_hide.md`）**：

1. shell 能驱动的**通用隐藏名单不存在**：
   - 云控 `CloudSettings` 写入要 signature|privileged 权限；
   - 企业版隐藏名单要 `persist.sys.ent_activated`；
   - cust 配置在只读 erofs 上；
   - device_config / FeatureFlags 不管这些小米条目；
   - 设备上已有账号，设不了 device owner。
2. 唯一的官方开关板是「更多设置 → 应用扩展功能」（`ex_func`，Settings 私有 SharedPreferences，adb 写不进）。当前只出现 5 项，而且**已经全部关闭**，其余 9 项因为对应的包删了，勾选框本身就不出现。
3. 删包只对「检查包或 intent 是否存在」的条目有效。首页小米账号栏不属于这类：它只在国际版或 `global maintenance_mode_user_id == 110` 时隐藏。

**maintenance_mode_user_id 的全系统读者审计**（写入前做）：

- **扫描范围**：拉取 user 0 的全部 APK 和框架 jar，覆盖 570/587（没拉到的 17 个是 vendor/overlay）。扫 dex 字符串里的键名和 `isInMaintenanceMode`，12 个命中文件逐个反编译。
- **结论**：在「只有 user 0、不存在 user 110」的前提下，真正生效的只有 Settings（隐藏账号栏、禁止改锁屏密码）。
  - services.jar 的 `ComputerEngine.getPersistentApplications` 先判断 `exists(110)`，不成立就不读这个键。
  - miui-services、powerkeeper、lbe 权限、qualcomm.location、gnss.polaris、NFC 都只在自身进程属于 user 110 时生效。
  - securitycore 只写这个键、从不读；相机只上报错误计数。
  - SystemUI 和 native 代码不引用它。

**运行态验收**：
- 写入后 120 秒：system_server / SystemUI / Clash / NFC 的 PID 不变，RescueParty 缓解计数不变，VPN 在线。
- 然后 `svc power reboot`：开机原因 `reboot,2000`，90 秒内无系统级崩溃，SystemUI pid 稳定。
- `tools/postboot_check.sh` 全绿。唯一的红项是 boot reason 历史里 07:24/07:25 的事故记录，属于历史。
- 所有改动重启后仍在。

## 三、结果

| 操作 | 原值 → 新值 | 界面效果 |
|---|---|---|
| `pm uninstall --user 0 com.xiaomi.account` | 已装 → 未装 | 系统同步清掉 `com.xiaomi` 账号。这个包持有 RECEIVE_SMS，每次打开账号页都会上传 userId/OAID/机型/token |
| `settings put global maintenance_mode_user_id 110` | null → 110 | 首页「登录小米账号」消失，首页 21 → 20 项 |
| `settings put secure quick_control_all_devices 0` | 1 → 0 | 「实时发现周围设备」原本**开着、一直在扫**，而它依赖的融合设备中心 milink 早已删除 |
| `settings put secure smart_device_control 0` | null → 0 | 智能设备控制设为「无」，上一行随之隐藏 |
| `settings put secure second_space_entrance_status 0` | null → 0 | 隐私与安全里的「手机分身」消失（UI 已核验） |
| `settings put system three_gesture_up none` | launch_ai_memory → none | 三指上滑不再指向已删的 AI 应用 |

桌面图标和控制中心磁贴核对后本来就干净：小米自家的只剩相机、录音机、指南针（待定）、设置；磁贴里没有已删功能。

**代价**：维修模式标记为 110 期间，Settings 禁止设置或修改锁屏密码。要改时先 `settings delete global maintenance_mode_user_id`，改完再 put 110。

## 四、仍保留与理由

**隐藏不了的（代码写死，无 root 没办法）**，均已关闭或已是死入口：
- 用户体验改进计划、使用情况和诊断、广告服务
- 「我的设备」的系统更新卡片：每次打开这个页面都会调起 updater 检查更新，小米域名已被 Clash 拦截
- 小米换机、应用升级提醒、资源推荐
- SIM 保护、骚扰拦截、电诈防护、预警类
- 实时字幕（小米闻声）、来电秀、小米隐私保护措施网页链接

**刻意保留**：
- 备份与恢复：谷歌原版也有，其中含 Google 备份。它现在已被 ex_func 关闭，这是既有状态，没有去动。
- 屏幕录制：控制中心里有它的磁贴，在用。
- 健康使用手机：本地功能，对应谷歌的「数字健康」。

**仍留给用户决定的包**：thememanager / screenrecorder / compass / misound / updater。
