## 三、建议（按优先级；本次**一项都没有执行**）

**P1（本周）**
1. **重新处理回来的 18 个包，先做对照实验找原因**
   - 挑一个低风险的（如 `com.miui.cit`）：卸载后等 ≥2 分钟，确认 `dumpsys package com.miui.cit | grep "User 0"` 显示 `installed=false`，再 `adb reboot`，开机后复查。
   - 等够时间后能留住 → 原因是重启太快：以后每批卸载后先核对再重启。
   - 等够时间还是回来 → 是 HyperOS 开机还原：这批改用 `pm disable-user`，或者接受「只断网」。
   - 验收标准改为：**重启后** `pm list packages --user 0` 与 `removed.txt` 的交集为空。
2. **`passport_ad_status` 重新设为 OFF，并加入每次开机后的自检**。小米账号 App 会改回来；它已经断网，实际影响很小，但属于「设置被静默改回」，应该纳入监控。
3. **确认并删除 AdGuard 留下的用户 CA**：设置 → 密码与安全 → 系统安全 → 加密与凭据 → 信任的凭据 → 用户。shell 无权读取，只能在手机上看。
4. **修 Clash 策略**（改 `tools/gen_clash_config.py`）：
   - a) `profile` 加 `store-fake-ip: true`，避免重启后 fake-ip 被复用、流量串到别的域名（WhatsApp → qq.com 那条）。
   - b) 显式加 `DOMAIN-SUFFIX,rcpc-sdk-access.m.qq.com,REJECT`（以及 `-v6`）。目前只有按进程名拦，其他进程连它会放行。
   - c) 决定 `PROXY: fallback [HOME, DIRECT]` 要不要保留 DIRECT。保留时，重载或 WG 故障期间，非小米流量会直连（本次在家里仍经过 Surge，**在外面就是直接走运营商**）。想要「宁可断网也不直连」，就去掉 DIRECT；代价是家里的 Mac mini 宕机时手机就上不了网。
