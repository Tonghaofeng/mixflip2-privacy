# 复盘：病毒扫描「上传应用特征到云」为什么漏网（2026-10-01）

## 发生了什么
09-30 精简时为了 adb 装包，**故意保留** `com.miui.guardprovider`（病毒扫描/云查杀/电诈引擎），只在 Clash 里断网。
10-01 20:02 和 22:08，安全中心按「7 天未扫描」发提醒；用户点进去看到「使用云扫描：上传应用包名和应用特征至云病毒引擎（合作方）」授权框。
网络层没漏：安全中心 UID 1000、guardprovider 都被 Clash 拒；但**功能、授权入口、特权都还在**，用户被吓到是对的。

## 其实早有信号
- 10-01 06:50 体检报告第 3 节：`com.miui.guardprovider → rcpc-sdk-access.m.qq.com（腾讯 SDK）` ×4，**被拒**。当时记成「已拦截 ✅」，没人追问「杀毒引擎为什么连腾讯、背后是什么功能」。
- 同一份体检第 3c 节：持有系统网络权限的身份（1000/1001/10134/10229…）显式绑定物理网卡即可**绕过 VPN 锁定**。所以「只断网」本来就不是密封的。
- 体检列了 13 条建议，结尾写「本次一项都没有执行」。之后几个会话各做各的，**没有人把它们跟踪到关闭**：registration 短信自注册、rcpc 拒绝规则、store-fake-ip、AdGuard CA、accept.py 的 `logcat -c` 全挂到今晚。

## 根因（方法层面）
1. **验收只看网络**。accept.py / uid_domain_audit.py 只回答「有没有连出去」，回答不了「这个包还能干什么」。「连接被拒」被当成了结论，其实它是线索：说明有个活着的功能在试图上报。
2. **「保留但断网」的包没有做能力盘点**。为了 adb 装包这点便利，留下了一个能截获通话音频、读写全盘文件、写安全设置的包。断网只封住一个出口：弹窗授权、本地扫描、身份绕过锁定都封不住。
3. **只看当下，不看定时**。提醒要「7 天未扫描」才触发，精简那两天根本看不到；也没有盘点保留包的 JobScheduler 任务、闹钟和通知渠道。
4. **建议没有闭环机制**。体检结论写在报告里，没有进待办表，下一个会话不会主动去看。

## 本会话自己的错（如实记录）
- 我说过「UID 1000 无网、锁定模式下没有外泄窗口」，**说过头了**。体检 3c 早就写明系统身份可绕过锁定。正确说法是：普通 socket 被拒；显式绑定物理网卡的路径，在家有 Surge 兜底，走蜂窝时没有观测手段。
- 先构建空壳 com.miui.securitymanager 再去装，结果撞上小米保留包名签名强校验（-22）。应该先查安装侧限制，再动手。
- 跑 accept.py 时它的 `logcat -c` 清掉了我正要查的 Clash 日志。这个坏习惯体检第 13 条已经指出，但一直没改。今晚已改成 `logcat -T`。

## 改进（已落地）
| 问题 | 措施 |
|---|---|
| 只有网络审计 | 新增 `tools/feature_audit.py`：按「能力 + 触发点」盘点厂商包（敏感/特权权限、任务、闹钟、近 7 天通知、高权位、开着的同意/云/上报类键），与 accept.py 并列做验收 |
| 被拒连接当结论 | 规则：每条被拒的小米/国内连接都要追到具体功能，能删就删；只断网是最后手段，要写理由 |
| 保留包无人复审 | KEEP.txt 只放「删了会坏系统」的包；「保留只断网」的包另列到 `debloat/OPEN_ITEMS.md`，写清特权、任务和保留理由 |
| 定时功能看不到 | feature_audit 盘点任务、闹钟、通知；精简一周后再跑一次，抓时间触发的功能 |
| 建议无闭环 | `debloat/OPEN_ITEMS.md`：体检/审计的每条建议进表，写状态；每次会话开始先看、结束更新 |
| accept.py 清日志 | 改为只读开始时间之后的日志 |
